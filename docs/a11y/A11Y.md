# A11Y.md — Fractionator's accessibility standard

> **Source & attribution.** This ruleset is adapted from
> [`fecarrico/A11Y.md`](https://github.com/fecarrico/A11Y.md) (MIT-licensed), a
> persistent-context protocol that maps WCAG 2.2 AA to concrete, testable rules
> for AI-assisted development. It is vendored here, trimmed to what Fractionator's
> generated HTML report actually needs, so the standard travels with the repo.

Fractionator's product is a **self-contained HTML report** (`src/build-report.js`).
This file is the standard that report must meet. Treat it as persistent context:
when you add or change anything interactive in the report, satisfy these rules or
record a deliberate deviation in [`EXCEPTIONS.md`](EXCEPTIONS.md).

## Severity matrix

| Level | Label | Definition | Action |
|-------|-------|------------|--------|
| 🔴 | CRITICAL | Blocks the task; breaks keyboard or modal focus | MUST FIX |
| 🟠 | HIGH | Perception / readability; raises error & abandonment | MUST FIX |
| 🟡 | MEDIUM | Reduces efficiency; missing optional affordances | SHOULD FIX |
| 🔵 | LOW | Cosmetic polish | MAY FIX |

## Testable rules

### Perceivable
- **Contrast** — text ≥ **4.5:1**; UI components & focus indicators ≥ **3:1**;
  text ≤ 10px should reach **7:1**.
- **Never rely on colour alone** — pair state with icon + text (e.g. an "off-scale"
  badge alongside the coloured bar).
- **Images** — every informative `<img>` carries a functional `alt`.

### Operable
- **Keyboard** — 100% of functionality works without a mouse. Every clickable
  element has a keyboard equivalent (Enter/Space for buttons; arrow keys for
  composite widgets).
- **Focus** — always visible, **≥ 2px**, never suppressed. Modals trap focus and
  return it to the trigger on close.
- **Target size** — aim for **44×44 CSS px**; smaller is acceptable only with
  ≥ 8px spacing or an equivalent larger target (see exceptions).
- **Motion** — honour `@media (prefers-reduced-motion: reduce)`.

### Understandable
- **Labels** — every form control has a programmatic name via `<label for>`,
  `aria-label`, or `aria-labelledby`. A placeholder is **not** a label.
- **Dynamic feedback** — announce content changes (filter results, etc.) via
  `aria-live` / `role="status"`.

### Robust
- **Semantic HTML first** — native `<button>`, `<table>`, `<details>`, landmarks
  (`<main>`, `<header>`) over `div` soup.
- **APG patterns** — for composite widgets (tabs, dialogs) follow the
  [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/).

## Anti-patterns (prohibited)
- ❌ A clickable `div`/`span`/`article` with no `role`, `tabindex`, or key handler.
- ❌ A modal that leaks focus or doesn't restore it on close.
- ❌ `placeholder` used as the only label.

## Definition of done
- [ ] `npm test` passes (includes the structural a11y assertions in
      `src/build-report.test.js`).
- [ ] Tab order validated manually; every interaction works without a mouse.
- [ ] Layout survives 400% zoom.
- [ ] Removing colour loses no information.
- [ ] Any rule not met is logged in [`EXCEPTIONS.md`](EXCEPTIONS.md) with a reason.

## How to use this when changing the report
1. Before adding an `onClick`, prefer a native element; if not possible, add the
   full ARIA + keyboard behaviour.
2. New interactive element ⇒ keyboard path + visible focus + accessible name.
3. Re-run `npm test`; do the manual keyboard/zoom pass in [`REPORT.md`](REPORT.md).
